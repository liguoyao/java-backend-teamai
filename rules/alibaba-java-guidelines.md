# Java 开发规范

以[阿里巴巴 Java 开发手册（黄山版）](https://github.com/alibaba/p3c)为依据；以下为适用于本项目的摘要，完整要求以官方手册为准。修改既有代码时遵循现有架构和兼容性约束，不为格式重写无关代码。

## 命名与格式

- 类名使用 UpperCamelCase，方法和变量使用 lowerCamelCase，常量使用全大写和下划线；名称表达业务含义，避免拼音英文混用和难懂的缩写。
- 包名使用小写；抽象类以 Abstract 或 Base 开头，异常类以 Exception 结尾，测试类以 Test 结尾。
- 使用四个空格缩进，保持代码格式与项目一致；分支和循环使用大括号，避免过长方法和过深嵌套。
- 公共类型和接口、复杂业务逻辑应有准确的文档或注释；修改行为时同步更新注释，不写重复代码含义的注释。

## 集合、并发和异常

- 比较包装类型的值使用 equals；处理可空值时先保证比较安全。金额等精确小数使用 BigDecimal，避免通过浮点数构造。
- 遍历集合时不直接通过集合的删除方法修改集合；使用迭代器或适当的集合操作。注意集合为空、容量及并发访问的边界。
- 线程池应明确配置容量、队列和拒绝策略，并管理生命周期；共享可变状态应有明确的线程安全措施。ThreadLocal 使用后及时清理。
- 不吞掉异常或用异常控制正常流程；在合适的边界处理异常，保留原因和必要上下文。资源使用 try-with-resources 或可靠关闭。

## 日志、安全与数据

- 使用项目的日志门面和参数化日志；记录有诊断价值的上下文，避免重复记录同一异常，禁止记录密码、令牌等敏感信息。
- 校验外部输入和权限；使用参数化查询，避免拼接不可信输入；对外输出避免泄露内部异常和敏感数据。
- 数据库访问避免循环查询和无界查询；事务范围保持合理，涉及并发更新时明确一致性策略。

## 设计与测试

- 方法职责清晰，接口保持兼容；避免重复实现和过早抽象。空值、边界条件和失败路径应明确处理。
- 对业务逻辑及缺陷修复编写有意义的测试，覆盖关键成功、边界和失败场景；测试应独立、可重复，不依赖生产数据或外部服务的偶然状态。
